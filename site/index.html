Kernel families

A reusable algorithm shelf

The repository is organized by domain so applications can depend on focused crates instead of a single all-purpose utility package.

Collections

Bit sets, Fenwick trees, arenas, LRU caches, ring buffers, sparse sets, union-find.

Geometry

Small geometry operations intended to compose into rendering, collision, and spatial systems.

Spatial

Broad-phase and spatial indexing kernels designed for deterministic parity checks.

Graphs

Graph algorithms and structures kept independent from application-specific graph models.

Search

Reusable search primitives with explicit semantics and testable reference behavior.

Statistics

Numerical building blocks intended for profiling, analysis, and data-processing pipelines.

Repository contract

Why these kernels exist

  1. Correctness first. New optimized implementations are checked against simple oracles.
  2. Determinism by default. Reproducible inputs and outputs make performance work debuggable.
  3. Small boundaries. Kernels stay usable from native Rust, WASM, benchmarks, and higher-level applications.
  4. Performance with evidence. Optimization claims belong next to repeatable measurements.
