Reading the labels

Big-O describes growth, not a stopwatch

The complexity labels describe how work or memory grows as the input gets larger. They are properties of the algorithmic path shown here, not browser benchmark measurements.

O(1)
Fixed work as input grows.
O(log n)

O(n)
Work grows proportionally with input size.
O(n²)

α(n)
Inverse Ackermann; effectively constant for practical union-find sizes.

Fenwick tree

Beyond the live labs

The repository stays broader than the demo

The same focused-crate model also covers geometry, graphs, similarity, broad-phase spatial search, caches, queues, bit sets, sparse storage, sorting, and more. The live examples are a browser-facing teaching layer over those reusable kernels, not a replacement API.

Repository contract

What the browser demo is allowed to claim

  1. Rust owns behavior. Live results come from the same crates used by native consumers.
  2. Big-O is explanatory. Complexity labels describe algorithm growth; they are not wall-clock benchmark claims.
  3. Correctness remains test-owned. The interactive page demonstrates behavior but does not replace oracle and differential tests.
  4. Performance evidence remains separate. Deterministic benchmarks and regression sentinels stay in the repository performance contract.
